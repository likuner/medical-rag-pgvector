# 用 LlamaIndex 重写分块逻辑并重建库

（与上一版计划相同；已补充确认：项目有 `.venv`（Python 3.12.14），因目录改名 `pip` 脚本 shebang 失效，统一用 `.venv/bin/python -m pip` 安装即可。）

## 目标
清空数据库，重新抓取 5 个中文医学站，把 `chunking.py` 的手写分块替换为 **LlamaIndex `SentenceSplitter`**（embedding 仍为 GLM 1024 维，站点与流程不变）。

## 关键调研结论（已验证）
- `llama-index-core==0.14.24` 经 pip dry-run 与现有锁定版本（numpy 1.26.4 / transformers 4.44.2 / torch 2.2.2 / sklearn 1.5.2）**无任何冲突**。
- `SentenceSplitter.split_text(text) -> list[str]`；`chunk_size`/`chunk_overlap` 单位为 tokenizer 计数；自定义 `tokenizer` 需返回序列（内部 `len()`）。
- 默认句级切分是英文 Punkt，中文需自定义 `chunking_tokenizer_fn`（复用现有 `[。！？!?.；\n]` 正则）。
- 自定义 tokenizer 后 **tiktoken 永不调用**（规避国内网络 BPE 下载问题）；nltk/tiktoken 数据已内置 wheel，离线安全。
- 不用 `SemanticSplitterNodeParser`：需逐句调 embedding API，成本高、收益边际。GLM embedding-3 输入上限 3072 tokens，512 token 分块余量约 6 倍。

## 代码改动

1. **`requirements.txt`**：新增 `llama-index-core==0.14.24`。
2. **重写 `medical_rag/chunking.py`**——公共 API 不变，`pipeline.py` 零改动：
   - 保留：`Chunk` 数据类（index/text/char_length/token_count/as_row）、`count_tokens`。
   - 删除：`split_sentences`、`_cut_long`、`_apply_overlap` 等手写逻辑。
   - 新增：`_tokenize(text) -> list`（`_TOKEN_RE.findall`，中文字=1/英文词=1）；`chunk_document` 构造
     `SentenceSplitter(chunk_size=cfg.size, chunk_overlap=cfg.overlap, tokenizer=_tokenize, chunking_tokenizer_fn=中文句界正则)` 调 `split_text`；
     保留 `overlap >= size` 防御、`min_chunk` 过滤与重编号。
3. **`config.py`**：`ChunkConfig` 语义从「字符」改为「token」：默认 `CHUNK_SIZE=512`、`CHUNK_OVERLAP=100`（约保持原 600 字符块与 20% 重叠比例），`min_chunk=80` 仍按字符。
4. **`README.md`**：分块一节与环境变量表更新为 LlamaIndex SentenceSplitter / token 单位。
